Why Manual localStorage is Redundant When Zustand is Active

When an enterprise application already relies on Zustand for global store management, accessing localStorage directly in component hooks creates technical debt:

  • Reactivity Loss: Manual localStorage updates don't cause components to re-render without hacky custom event dispatchers.
  • Hydration Drifts: Manual JSON parsing inside useEffect or useState is error-prone and causes hydration mismatches when switching merchant business accounts.
  • Declarative Solution: We created useCustomerStore with Zustand's persist middleware and createJSONStorage(() => localStorage). Components subscribe reactively, and persistence happens automatically behind the scenes.
src/store/useCustomerStore.ts 
export const useCustomerStore = create<CustomerStoreState>()(
  persist(
    (set) => ({
      customCustomers: {},
      addCustomCustomer: (businessId, customerInput) =>
        set((state) => {
          const key = String(businessId);
          const list = state.customCustomers[key] || [];
          const newCustomer: CustomerRow = {
            ...customerInput,
            id: `cus-${Date.now()}`,
            addedOn: formatDisplayDate(),
          };
          const filtered = list.filter(
            (c) =>
              !c.email ||
              !customerInput.email ||
              c.email.trim().toLowerCase() !== customerInput.email.trim().toLowerCase()
          );
          return {
            customCustomers: {
              ...state.customCustomers,
              [key]: [newCustomer, ...filtered],
            },
          };
        }),
    }),
    {
      name: "bitnormous-customer-store",
      storage: createJSONStorage(() => localStorage),
    }
  )
);

Professional Skeletons vs. Primitive Text Placeholders

Displaying dummy text like time: "Loading...", activity: "Loading activity..." looks unpolished, shifts layout widths during initial mount, and degrades perceived performance.

We refactored DataTableCard and all page consumers to use Column-Adaptive Pulsing Skeletons:

Timestamp Column: Fixed w-28 / w-32 pulsing pill Activity Column: Alternating w-4/5 max-w-lg and w-3/5 max-w-md Zero Layout Shift (CLS = 0) Passes isLoading={true} directly to table engine

AuditLogDetailInspector Forensics Console

Instead of dumping raw strings into an aside, the new AuditLogDetailInspector provides an interactive, enterprise-grade inspection deck:

  • Domain Themed Badges: Webhook Dispatch (Indigo), Checkout Order (Emerald), Ledger Settlement (Amber), and Access Control (Purple).
  • Live Pulse Status: Real-time HTTP status indicators (HTTP 200 OK, Pending, Failed).
  • One-Click Clipboard Actions: Instant copy with temporary checkmark feedback for Event IDs and JSON payloads.
  • Tabbed Forensic Views: Toggle between human-readable Structured Properties and syntax-styled Raw JSON.
